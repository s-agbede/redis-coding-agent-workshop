# Architecture asset brief

Seven finished SVG diagrams follow the established Part 1 palette and a consistent progressive architecture. Each includes an accessible title and description; lesson image links supply meaningful alt text. The diagrams use a 560-pixel viewBox and have been visually checked at 368 pixels and verified in the actual browser lesson panel at approximately 312 pixels, with no horizontal overflow.

Keep one base arrangement: terminal at left; harness/context centre; model at right; tools below; independent verification outside the model loop. Keep position and colour consistent: project instructions, session conversation, retrieved preferences and retrieved procedure must remain distinguishable without colour alone.

Use progressive overlays on the base architecture. Distinguish asynchronous extraction from synchronous request assembly; do not suggest every turn waits for extraction. Label a second Playbook consumer as potential, using a dashed line unless demonstrated. Do not imply publishing automatically integrates another agent or that owner filters establish authorization. Context does not update model weights.

Each diagram should answer one prediction question in its lesson, with concise labels and no service credentials. Final rendered layouts must be checked in the actual narrow browser lesson panel.
